**1. Issue Confirmation: YES, real problem**
With SQLAlchemy's `yield_per()`, the generator holds an open DB cursor bound to the session. If the session commits/closes before full consumption, subsequent `next()` calls raise `InvalidRequestError: This transaction is inactive`. 

**2. Why it's problematic**
The risk exists at the `ExportService` level, not just `BaseRepository`. In `export_service.py:24-40`, each streaming method yields inside a `with self.uow:` block. Because the function itself is a generator, the `with` block suspends at each `yield`. If the consumer stops iterating (break, exception, partial consumption), the `__exit__` closes the session. The pattern works currently only because `export_to_markdown` consumes each generator fully before moving on. Any refactor that decouples generator creation from consumption (e.g., passing the generator to another async consumer, caching it, or iterating lazily later) will trigger the bug.
