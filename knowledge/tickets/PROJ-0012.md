# Create Orval stubs for FastAPI server

> **Workflow Status**: Requirements gathered ✓ → Planning complete (plan in knowledge/plans/) ✓ → Implementation complete ✓ → Testing complete ✓ → Done

## Problem Statement & Business Context

**What problem are we solving?**
We're about to build a frontend for the plant tracking app but have no TypeScript API client. The frontend team would need to manually write fetch calls, type definitions, and request/response types for every endpoint. This is error-prone, slow, and falls out of sync when the API changes.

**Why is this important?**
Orval generates type-safe API client stubs directly from the FastAPI OpenAPI spec. This gives us:
- Auto-generated TypeScript types for all request/response models
- Ready-to-use API hook functions (React Query, etc.)
- Single source of truth — stubs stay in sync with backend
- Faster frontend development with no manual boilerplate

**Who needs this?**
Frontend developers building the plant tracking web application.

## Requirements & Scope

### Must-Have Features
- OpenAPI spec export script for FastAPI backend (generates `backend/fastapi/openapi.json`)
- Orval configuration file (`orval.config.ts` or `orval.config.cjs`) wired to the exported spec
- Generated TypeScript stubs output to `frontend/src/api/`
- Generated types for all request/response models from all current endpoints:
  - Health endpoint
  - Plants endpoint (`/api/plants/care-needed`)
  - Media attachments endpoint (`/api/media/*`)
- npm script to run code generation (e.g., `npm run generate:api`)
- Generated files excluded from git (in .gitignore) or committed per team preference
- Code generation works with `npm install` + `npm run generate:api` without backend running

### Nice-to-Have Features
- React Query (TanStack Query) hooks generated alongside types
- Automated codegen on CI when backend spec changes
- Watch mode for local development (`orval watch`)
- Custom axios/fetch instance configuration for base URL, auth headers, etc.
- Swagger UI serving the spec locally during dev

### Out of Scope
- Frontend UI components or pages
- Backend API endpoint changes or additions
- Authentication/authorization integration in stubs
- Mobile app API client
- API documentation website

## Constraints & Context

**Integration Points**:
- FastAPI backend at `backend/fastapi/` — OpenAPI spec sourced from `plant_tracking_api.main:app`
- Frontend application at `frontend/` (not yet created)
- Existing project tooling: Justfile, uv for Python, npm for JS tooling

**Preferred Technologies**:
- Orval (latest stable) for codegen
- TypeScript for generated stubs
- npm for running Orval (already in project via package.json)
- React Query hooks if the frontend uses React

**Constraints**:
- Spec must be generated from the FastAPI app programmatically (not manually curated)
- Generation must work without a running backend server
- Generated code must pass linting (align with frontend lint config once established)
- Must be compatible with whatever frontend framework is chosen (React, Vue, etc.)

## Success Criteria

- [ ] `npm run generate:api` completes without errors and produces files in `frontend/src/api/`

- [ ] OpenAPI export script runs and produces valid `backend/fastapi/openapi.json`
- [ ] Generated stubs contain type definitions for all three endpoint groups (health, plants, media)
