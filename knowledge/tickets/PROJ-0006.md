# Capture activity log entries on a plant

> **Workflow Status**: Requirements gathered ✓ → Ready for `/create_plan_generic` to research and plan

## Problem Statement & Business Context

**What problem are we solving?**
The plant-tracking CLI has core plant records, genus, and seed packet functionality, but no way to track day-to-day care activities. Users need to log watering, humidity, fertilizer applications, and general notes against individual plants to maintain a care history.

**Why is this important?**
Growing plants requires tracking care routines over time. Without structured logs, users lose visibility into watering schedules, fertilizer applications, and observations that could explain plant health changes.

**Who needs this?**
Gardeners/plant owners using the `plant-tracking` CLI to manage their plant collection.

## Requirements & Scope

### Must-Have Features

**New CLI command: `plant-tracking log`**

Four event types:
1. **Humidity** — `plant-tracking log <plant-id> humidity --level 6 [--date YYYY-MM-DD]`
   - Level is a number (e.g., 6 on a 1-10 scale)
2. **Watering** — `plant-tracking log <plant-id> water --amount 4qt [--date YYYY-MM-DD]`
   - Amount with unit; must be validated and normalized (e.g., "4qt", "1L", "500ml")
3. **Fertilizer** — `plant-tracking log <plant-id> fertilizer --type Tomorite --strength 1/2 [--date YYYY-MM-DD]`
   - Type (name/brand) and strength/concentration
4. **Note** — `plant-tracking log <plant-id> note --text "Leaves look yellowish" [--date YYYY-MM-DD]`
   - Free-form text

**List command:**
- `plant-tracking log <plant-id> list` — display all log entries for a plant as a table

**Storage:**
- Single consolidated log file: `database/logs/plant-activity-log.md`
- YAML-based format (one file, all plants' entries)
- Each entry contains: plant_id, event_type, timestamp, and event-specific fields
- Event_type field is searchable for future filtering

**Date handling:**
- `--date YYYY-MM-DD` flag on all add commands
- Default to today's date if `--date` is omitted

**Validation:**
- Validate plant_id exists before allowing log entries
- Validate and normalize water amount units
- Validate date format

**Testing:**
- Unit tests for all log entry creation, validation, and list functionality
- Must follow existing test patterns in `tests/test_plant_tracking.py`

**Documentation:**
- Update `README.md` with new command usage

### Nice-to-Have Features
- Filter log list by event type: `plant-tracking log <plant-id> list --type water`
- Export log data to CSV

### Out of Scope
- Edit/delete existing log entries (needed later, not now)
- Database migration (eventual goal, not part of this ticket)
- Log aggregation/analytics dashboards
- Notifications or reminders
