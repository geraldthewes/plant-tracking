# Create plant entry and print label

> **Workflow Status**: Requirements gathered ✓ → Ready for `/create_plan_generic` to research and plan

## Problem Statement & Business Context

**What problem are we solving?**
Gardeners need to quickly register a new plant with a unique ID and get a printable QR code label for their pots. This is the first step in the plant lifecycle tracking flow — without a label, there's no physical connection between the plant and its digital record.

**Why is this important?**
This enables the core QR-Physical-Digital integration that is the foundation of the entire plant tracking system. Every plant needs a durable identifier that links the physical pot/stake to its digital record.

**Who needs this?**
Home gardeners (primary user: "Alex" from PRD) who want to track individual plants through their growing season using data-driven insights.

## Requirements & Scope

### Must-Have Features
- **`create-plant` command**: Interactive CLI that prompts for all plant fields from the PRD (variety name, Latin name, brand, days to maturity, germination time, planting depth, spacing, sun requirements, indoor start time, planned planting date). Auto-generates ID in VARIETY-YYYY-SEQ format. Saves markdown entry to `database/` directory.
- **`create-label` command**: Takes a plant ID, generates a 40x30mm PNG label image with: left side = text fields (variety name, Latin name, planting date), right side = QR code encoding the plant ID, one line of text at bottom. Displays PNG for review. Saves to `database/` directory.
- **`print-label` command**: Takes a plant ID or label file path, sends the PNG to the Phomemo M120 Bluetooth printer. (Printing is a separate concern from label generation.)
- **`database/` directory**: Local markdown files to store plant records and generated label PNGs.

### Nice-to-Have Features
- None for this ticket

### Out of Scope
- Seed packet scanning/OCR (separate ticket)
- QR code scanning / plant record retrieval
- Hermes agent integration
- Mobile app interface
- Photo attachment capability
- Editing/updating plant records after creation

## Constraints & Context

**Integration Points**: `database/` local markdown storage directory

**Preferred Technologies**: Python CLI tool

**Constraints**:
- Label dimensions: 40x30mm
- ID format: VARIETY-YYYY-SEQ (e.g., HABY-2026-001)
- Label printing uses Phomemo M120 Bluetooth printer via existing phomemo-tools filtering pipeline
- No external dependencies beyond standard Python + common libraries

## Success Criteria

### Automated Verification
- [ ] `create-plant` command creates a valid markdown file in `database/` with all required fields
- [ ] Auto-generated ID follows VARIETY-YYYY-SEQ format and increments correctly
- [ ] `create-label` generates a valid PNG image at 40x30mm dimensions
- [ ] `print-label` successfully sends label to M120 printer
- [ ] QR code encodes the plant ID correctly and is scannable
- [ ] Label layout matches specification (text left, QR right, one line bottom)
- [ ] All CLI commands show helpful usage when called without arguments

### Manual Verification
- [ ] Interactive prompts capture all plant fields correctly
- [ ] Generated label image is clear and readable
- [ ] Markdown plant record contains accurate, well-formatted data
- [ ] PNG displays correctly for review before any print operation

**End State**: A gardener can run `create-plant`, enter seed variety information, get a markdown record saved, run `create-label` to get a printable QR label PNG for review, and optionally run `print-label` to send it to the M120 printer.

## Research Questions for Planning Phase

The following should be investigated during `/create_plan_generic`:
- How to best generate QR code + label layout in Python for 40x30mm labels?
- What Python libraries work well for label image generation (e.g., `qrcode`, `Pillow`)?
- How should the markdown plant record be structured (YAML frontmatter + markdown body)?
- What's the ID generation algorithm (parse variety abbreviation, current year, sequence from existing entries)?
- How should the interactive CLI prompts be structured (e.g., `rich` for nice prompts)?
- What existing phomemo-tools patterns should we follow for printing pipeline?
- How does the M120 printing work (Bluetooth, USB, cups filter)?
