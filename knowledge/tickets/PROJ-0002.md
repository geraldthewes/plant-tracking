# Track seed packet in its own schema

> **Workflow Status**: Requirements gathered ✓ → Ready for `/create_plan_generic` to research and plan

## Problem Statement & Business Context

**What problem are we solving?**
When creating a new plant entry, the same seed packet information (days to maturity, germination time, etc.) must be re-entered every time. This creates redundant, denormalized data across plant records.

**Why is this important?**
- Eliminates redundant data entry for repeated varieties
- Ensures consistency — days_to_maturity is stored once, not duplicated per plant
- Makes it easy to see all plants grown from the same seed variety

**Who needs this?**
Plant manager/gardener

## Requirements & Scope

### Must-Have Features
- New `seed_packets` schema/table with attributes:
  - `variety` — common name (e.g., "Yellow Habanero")
  - `latin_name` — scientific name
  - `brand` — seed brand/supplier
  - `days_to_maturity` — integer (e.g., 90)
  - `germination_time` — range string (e.g., "7-21")
  - `planting_depth` — string (e.g., "0.25")
  - `spacing` — range string (e.g., "12-18")
  - `sun_requirements` — string (e.g., "Full sun")
  - `indoor_start_time` — string (e.g., "8-10 weeks before last frost")
- Plant creation form supports selecting an existing seed packet
- Option to select "unknown" when no matching seed packet exists
- Migration of existing plant entries to populate seed_packets table
